## Findings by entry

### 1. swallowed-exceptions — candidates found

**real-defect** (2):

- `gakkari/ui/main_screen.py:381-385` (`_line_width`) — cue: *a function returning an empty/default value from inside an `except` block*. Bare `except Exception: return LINE_WIDTH_FALLBACK` around the widget query. No comment justifies the breadth; `NoMatches` is the only expected failure (pre-layout resize), and `Exception` also masks real breakage (e.g. a refactored-away `#list-view` selector silently renders every row at the 30-col fallback instead of failing visibly). Overlaps entry 21 (unreachable-after-mount guard) — fixing one fixes the other, so recorded here as primary.
- `gakkari/ui/main_screen.py:1047-1049` (`_refresh_notice_panel`) — same cue: `except Exception: return` around `query_one("#right-panel")`. This one is worse — it silently skips the entire panel refresh, so a genuine query failure leaves the notice board stale with no signal.

**legitimate-variant** (3 sites, verified reasons):

- `gakkari/__main__.py:12-15` and `gakkari/cli.py:81-84` — `except Exception: pass` around `stream.reconfigure(encoding="utf-8")`. The pattern is genuinely present, but the comment names a checkable reason ("no-op when the stream isn't reconfigurable (e.g. piped)") and it holds: `reconfigure` raises on non-reconfigurable streams, and failing there must not block `--help`/`--notice`. (A narrower `except (io.UnsupportedOperation, AttributeError, OSError)` would still be an improvement, but this is not the defect.)
- `gakkari/db.py:126-158` (`backup_db`) — outer `except Exception: return None` plus inner `except OSError: pass` on backup pruning (`db.py:154-157`). Docstring states the contract: "Best-effort: the backup must never itself put the app or data at risk, so any failure is swallowed and startup continues." Verified in code: skips cleanly when no DB exists (first run) and when today's snapshot exists; CLAUDE.md documents the same contract. The reason holds → legitimate-variant.

**false-positive-shape** (remainder — all verified against the checklist's guidance):

- `gakkari/db.py:113-116` (`get_conn`) — rolls back and **re-raises**; guidance: *re-raise after logging*.
- `gakkari/db.py:176-182` — `except sqlite3.OperationalError: pass` per `ALTER TABLE ADD COLUMN`; guidance: *narrow predicate catching one specific type*. CLAUDE.md documents the idempotent-additive-migration reason; it holds (re-running over an existing column raises exactly `OperationalError`).
- `gakkari/currency.py:49-54` — guidance: *handlers at I/O trust boundaries (network fetch), each naming its own reason*. The docstring's freshness ladder (`fresh`/`stale`/`missing`) is the stated reason and it holds: the failure is **not** hidden — the status string propagates to `_build_rate_cache`, which drives the `⚠ rate` / `⌛ stale` title-bar indicators.
- `gakkari/io.py:103, 117` and `gakkari/ui/subscription_modal.py:201, 216, 234, 247` and `gakkari/ui/settings_modal.py:152, 166` — narrow-tuple catches on row/field parsing; errors are collected per row and returned to the caller or surfaced via `notify`. Not swallows.
- `gakkari/ui/main_screen.py:245, 934, 949, 992` and `gakkari/ui/history_screen.py:99` — `except Exception as e` clusters that immediately `self.notify(..., severity=...)` with the error text. CLAUDE.md documents this contract ("DB-write failures … surface as notify rather than silent swallows"); verified at every site. Guidance: *defensive clustering at I/O trust boundaries with stated reasons*.
- `docs/index.html:614, 617` — `try { localStorage.setItem/getItem(...) } catch (e) {}`. Empty catch shape, but storage is an optional feature in an environment where storage can throw (private mode); failure degrades to "preference not persisted" and control flow continues correctly (`saved` falls through to the `navigator.language` default). Analogy of the *optional-dependency loading* guidance.

### 2. hardcoded-config-values — candidates found

**real-defect** (3):

- **Duplicated defaults table — `Settings` dataclass ↔ SQL schema.** `gakkari/models.py:116-129` re-declares every default that `gakkari/db.py:66-79` already declares in `SCHEMA` (`'USD'`, `'gross'`, `7`, `'0'`, `'en'`, `'estimate'`, `'date'`, `''` ×3, `1`). Cue: *two declarations of the same default*. The two tables are in sync today, but a change to one side silently changes behavior depending on which constructor path a value takes (`INSERT OR IGNORE` uses the schema default; code-built `Settings()` uses the dataclass default). Fails silently — the defect shape.
- **Duplicated cycle tuples + dead constants.** `gakkari/ui/main_screen.py:49-57` declares `_SORT_CYCLE` and `_TOTALS_CYCLE`; `gakkari/models.py:12-16` declares `TOTALS_VIEW_MODES` and `SORT_MODES` with identical contents — and grep shows the models-side tuples are imported nowhere (dead). Cue: *two declarations of the same default*. Drift consequence is silent: `action_cycle_sort` (`main_screen.py:891-892`) falls back to index 0 when the persisted mode is missing from the local tuple.
- **Layout ratio duplicated in code.** `gakkari/ui/main_screen.py:1054` computes the notice-panel width as `int(term.width * 0.40) - 4`, re-declaring the 60:40 split that lives in the CSS (`#center-panel { width: 60% }` / `#right-panel { width: 40% }`, same file). The comment documents the derivation, but if the CSS ratio ever moves this silently mis-measures (the call exists because `content_size` lags during resize — that reason holds; the *duplicated constant* is the defect).

**false-positive-shape** (checked, reasons hold):

- `currency.py:13-14` — `_FRANKFURTER_URL` / `_TIMEOUT = 5.0`: named module-level constants, single declaration point; CLAUDE.md documents frankfurter.dev as the fixed service.
- `notices.py:88-95` — `_BODY_MAX - 14`: comment explains the 14-col suffix budget; verified against both templates (`" renews today!"` = 14 cols; `" 今日更新！"` = 11).
- `main_screen.py:497` — `cap = 5` for by_category top-N: named local, display choice, fails loudly (visible truncation).
- Minor, same mechanism as the first finding: `cli.py:23` hardcodes `timedelta(days=7)` whose value is re-stated in the `--notice` help text (`__main__.py:27`). One line, no separate fix needed.

### 4. narrating-comments — candidates found → all false-positive-shape

### 5. near-identical-siblings — candidates found

**real-defect** (1, mild):

- `gakkari/models.py:70-90` (`next_renewal_after`) — cue: *long if-chain testing against a fixed list with structurally identical bodies*. Five `if self.billing_period == ...: return _add_months(d, N)` branches; four differ only in the month constant (weekly's `timedelta(days=7)` is the one semantic divergence). The same file already establishes the table idiom for period-keyed data (`_MONTHLY_FACTORS`, `models.py:19-25`) — a `_PERIOD_MONTHS` dict plus the weekly special case would halve the body and remove four repeated comparisons. Severity: maintainability only.

**false-positive-shape:**

- `io.py` `import_csv`/`import_json` and `cli.py:44` vs `notices._empty_body` — two instances each, below the "three or more" threshold.

### 7. inconsistent-error-handling — candidates found

**real-defect** (1):

- **Rate-failure visibility diverges between the two screens.** `MainScreen._build_rate_cache` (`main_screen.py:327-364`) uses `get_rate_status` and surfaces `stale`/`missing` via the `⌛`/`⚠` title-bar indicators; `HistoryScreen._rate_cache` (`history_screen.py:193-201`) uses bare `get_rate` (`history_screen.py:200`), discarding the status. Cue: *multiple files implementing the same role with different error contracts*.

### 23. off-by-one — candidates found

**real-defect** (1):

- `gakkari/cli.py:36` — cue: *`len(string)` used for display width (breaks on CJK)*. `lines.append("─" * len(header))` sizes the underline in **characters**, but `header` always contains one full-width weekday glyph (`(月)`…`(日)`, `cli.py:33`) and, under `--lang ja`, the title 【週間】更新予定スレ adds nine more double-width glyphs (`strings.py` `notice_thread_title`). The rule therefore renders ~1 cell short in EN and ~10 cells short in JA. The codebase already owns the correct primitive — `_disp_width` (`main_screen.py:62-69`, written exactly for this class of bug per its docstring); the CLI just doesn't use it.

**false-positive-shape:**

- `gakkari/notices.py:75-78` (`_truncate_name`) — char-count truncation of names, but the renderer crops again with rich's cell-aware `Text.truncate` (`notice_panel.py:58, 106, 122`), so the visible result is bounded; the builder pre-cut is a cosmetic heuristic, its stated reason ("avoids mid-glyph cuts") is coherent, and no overflow can reach the terminal.

## Uncategorized observations

Real issues no checklist entry covers:

1. **`--notice` output is only half-localized.** `cli.py` hardcodes English frame text — `!! TODAY ({n}):` (`cli.py:40`), `TODAY: nothing scheduled` (`cli.py:49`), `Upcoming (next 7 days):` (`cli.py:53`), `No upcoming renewals this week.` (`cli.py:62`) — while the thread title, weekday labels, and period names follow `--lang`. Under `--lang ja` the output mixes 【週間】更新予定スレ with English section headers, contradicting CLAUDE.md's "full EN+JA bundle covering all surfaces". The keys simply don't exist in `strings.py`.
2. **Dead constants.** `models.TOTALS_VIEW_MODES` / `models.SORT_MODES` (`models.py:12-16`) are imported nowhere — superseded by `main_screen._SORT_CYCLE`/`_TOTALS_CYCLE` (see entry 2). Remove or re-wire.
3. **Dead branch.** `models.gross_amount` (`models.py:58-62`): the `if self.tax_mode == "inclusive": return self.amount` branch is redundant — the fall-through returns the same value.
4. **Wrong error message reused.** `settings_modal.py:152-156` reports an invalid due-soon-days value with `err_amount_invalid` ("Amount must be a valid number (e.g. 9.99)") — misleading for a days field. Needs its own key.
5. **Cross-module private imports.** `cli.py:19` imports `_DAY_LABELS, _FACES_EMPTY, _post_id` from `notices` (no justification; these are load-bearing for CLI↔panel parity and should be public or the renderer should live in `notices`); `export_modal.py:12` imports `db._db_path` — that one carries a verified reason comment ("Resolve through the GAKKARI_DB seam"), so a public `db_path()` accessor is the cleaner fix.
6. **Mutate-then-persist.** `action_advance_renewal` (`main_screen.py:688`), `action_delete` (`:757`) and `action_resume` (`:775`) mutate the shared `Subscription` object **before** the DB write inside `get_conn()`. On write failure the transaction rolls back but the in-memory object stays mutated until the next `_load_subs()` — UI and DB briefly disagree. Persist-first (or reload-on-error) would close it.
7. **Coverage gaps** (tests are out of scope beyond entry 22, but noting): no tests for `currency.py` (the network/fallback ladder), `cli.render_notice` (where finding entry 23 lives), `db` settings round-trip, or any screen beyond `_status_options`.

Observation checked and *not* flagged: `mascot/` (12 files) looks like removal residue but `.gitignore` explicitly marks it a local-only scratch workspace, and `pyproject.toml` ships only `gakkari*` — intentional, untracked, not shipped. Version sync (0.4.2 in `pyproject.toml` / `__init__.py` / `docs/index.html:244`) verified intact.
