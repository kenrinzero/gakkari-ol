### `string-built-sql`
False-positive-shape.

Cue matched: *"`f"... {var} ..."` patterns"* — at [gakkari/db.py:144-148](gakkari/db.py:144):
```python
placeholders = ", ".join("?" for _ in statuses)
rows = conn.execute(
    f"SELECT * FROM subscriptions WHERE status IN ({placeholders}) ORDER BY next_renewal_date",
```

Triage: false-positive — *"Identifier interpolation that genuinely requires it."* The interpolated `placeholders` is a string of `?` markers computed from `len(statuses)`, not user data. ### `swallowed-exceptions`
Mixed: three real-defects, three legitimate-variants, two false-positive-shapes.

**Real-defects:**

1. [gakkari/ui/main_screen.py:233-240](gakkari/ui/main_screen.py:233) `on_mount` settings load:
   ```python
   try:
       with get_conn() as conn:
           self._settings = load_settings(conn)
           ...
   except Exception:
       pass
   ```
   Cue: *"`except Exception: pass` with no comment explaining the swallow"* + the canonical *"`# Memory is optional`" hermes-agent shape* (the project's analog of "settings are optional"). The swallow conflates "first-run, DB doesn't exist yet" (legitimate fallback to `Settings()` defaults) with "DB corrupted / migration partly applied" (operator should know). No log, no notify. The user opens the app and silently runs on default settings.

2. [gakkari/ui/main_screen.py:820-825](gakkari/ui/main_screen.py:820) `_persist_settings`:
   ```python
   def _persist_settings(self) -> None:
       try:
           with get_conn() as conn:
               save_settings(conn, self._settings)
       except Exception:
           pass
   ```
   Cue: same as above. Every settings toggle (`g`/`p`/`t`/`c`/`o`/`v`/etc.) silently fails to persist if DB write throws. User sees the UI update; next launch reverts.

3. [gakkari/ui/history_screen.py:94-97](gakkari/ui/history_screen.py:94) `on_mount`:
   ```python
   try:
       with get_conn() as conn:
           self._settings = load_settings(conn)
           entries = list_renewals(conn)
   except Exception:
       entries = []
   ```
   Cue: *"A function that returns `None`, `False`, or an empty default from inside an `except` block."* User sees an empty history with the "no renewals logged yet" message — indistinguishable from the genuine no-data case. Sibling concern with finding #1.

**Legitimate-variants:**

- [gakkari/db.py:117-118](gakkari/db.py:117) — `except sqlite3.OperationalError: pass` for idempotent `ALTER TABLE` migrations. Narrow exception type; the exception is exactly the "column already exists" case. Matches false-positive *"Best-effort retry/idempotency"*.
- [gakkari/ui/main_screen.py:347-353](gakkari/ui/main_screen.py:347) `_line_width` — falls back to `LINE_WIDTH_FALLBACK = 30` if the OptionList isn't queryable. The function's whole purpose is to *be* a fallback; the documented design is "give me a width, with sensible default." Internal helper, no external risk.
- [gakkari/ui/main_screen.py:856-860](gakkari/ui/main_screen.py:856) `_refresh_notice_panel` — `except Exception: return` if `#right-panel` isn't found. Defensive against widget-tree lifecycle (panel briefly absent during resize). No information lost; next refresh tick succeeds.

**False-positive-shapes:**

- [gakkari/cli.py:81-84](gakkari/cli.py:81) — `sys.stdout.reconfigure(encoding="utf-8")` wrapped with a documented comment explaining it's a no-op on non-TTY streams. Matches *"Genuine best-effort cleanup in shutdown paths"* (close analog: best-effort startup setup).
- [gakkari/currency.py:30-43](gakkari/currency.py:30) — `httpx.get` wrapped in `except Exception: rate = Decimal("1")` with module-level docstring explicitly documenting the graceful-degradation contract (*"On any network or parse failure, returns Decimal(\"1\") so totals degrade to raw amounts rather than crashing."*). The `except Exception` is broader than necessary; could be tightened to `(httpx.HTTPError, httpx.RequestError, KeyError, ValueError, json.JSONDecodeError)`. Borderline; tagging as false-positive because the documented intent is justified and the user-visible behavior (rate-fallback warning in the title bar via [`_fallback_currencies`](gakkari/ui/main_screen.py:312-319)) surfaces the failure mode.

## Compound findings

**Settings persistence chain (real-defect compound):**
The three real-defect findings under `swallowed-exceptions` (load at [main_screen.py:233](gakkari/ui/main_screen.py:233), save at [main_screen.py:820](gakkari/ui/main_screen.py:820), history-load at [history_screen.py:94](gakkari/ui/history_screen.py:94)) all share one root: *the project trusts the DB-write path to always succeed, with no operator signal when it fails.* If a migration partly succeeded — e.g. `init_db()` ALTER catches `OperationalError` correctly but the next attempt to `INSERT INTO settings` fails for an unrelated reason — the symptom is "settings revert on relaunch" with no log, no notify, no DB-error surface. This is the canonical *codified-guidance-defeated-by-its-own-implementation* shape: the migration code is correctly idempotent; the consumer code silently masks any other failure class.

Tightening proposal: replace the bare `except Exception: pass` blocks with narrow excepts (`sqlite3.Error`, `OSError`) AND `self.notify(...)` calls with `severity="warning"`. Three changes; all <5 lines each.

## Suggested fix order

1. **Real-defect (settings persistence swallows)** — [gakkari/ui/main_screen.py:233, 820](gakkari/ui/main_screen.py:233) and [gakkari/ui/history_screen.py:94](gakkari/ui/history_screen.py:94). High operator-impact: silent settings-revert and silent history-loss are exactly the failure modes the user can't debug.

3. **Cosmetic (currency.py exception broadness)** — narrow [gakkari/currency.py:41](gakkari/currency.py:41) `except Exception:` to the specific httpx + parse failures. Already documented as deliberate; tightening is defense-in-depth.
